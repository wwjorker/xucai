# 序采 · AI办公设备选购与采购平台

面向客户和商家的办公设备选购平台：普通商品可浏览、加入采购清单、确认下单；也可通过悬浮 AI 助手选品、咨询资料、调整清单。复杂采购再转商家核实方案。

## 功能

- 双端登录、身份隔离与会话续期。
- 六类办公设备、商品规格、资料版本、售价与库存。
- 普通采购清单、统一确认页、重复确认只创建一单、取消后归还库存。
- 真实会话历史、改名/归档、停止回复、可拖动缩放的聊天浮窗。
- 语义路由到通用交流、选购、资料咨询、采购订单四种角色；业务角色通过受控工具调用目录及交易接口。
- 商家上传商品图片、私有 OSS 存储和站内读取；新安装需配置自己的存储及有权使用的素材。
- 人工需求、分类数量、预算、用途与必须条件。
- 资料片段与出处定位，方案引用保留原文版本。
- 可选AI需求整理、向量检索与候选；默认关闭，生成结果须人工核实。
- 方案核实发布、订单快照、幂等确认与库存扣减。
- DEMO支付、虚构物流、收货及人工售后记录。

技术栈：Java17、Spring Boot3、Spring Cloud、MyBatis Plus、MySQL8、Nacos、Redis Stack、Spring AI 1.0.0 / Spring AI Alibaba 1.0.0.2；Vue3、Vite、Element Plus。六应用分别承担用户、认证、网关、商品目录、交易和AI职责。

## 本地运行

按[安装与运行](docs/安装与运行.md)准备新环境。需要JDK17、Maven3.8.1、Node22.12+、Python3.10+、Docker以及Windows上的PowerShell7。已验证Node24.14.0；Maven脚本使用3.8.1的`-llr`参数。

```powershell
./scripts/Build-Xucai.ps1 -Online -Goal package -JavaHome '<JDK17目录>' -Maven '<mvn.cmd路径>'
cd web
npm ci
npm run build
```

前端默认`http://127.0.0.1:5173`。演示账号为`buyer_demo`和`merchant_demo`，密码均为`XucaiDemo2026!`；这些是新库专用虚构账号，不能部署为真实经营账号。

启动后按[功能演示](docs/功能演示.md)走普通购物、AI对话和复杂方案三条路径。新安装默认关闭模型、尚无私人OSS图片，需自行配置；M720中国官网补充资料的可选添加方式见安装说明。

## AI 实现与验证边界

- 通过 Spring AI ChatClient 调用百炼，@Tool / @ToolParam 生成工具说明，Advisor 记录生成用量，EmbeddingModel 提供向量接口；关闭框架自动工具执行，由服务端控制白名单、有限执行轮次、身份与取消状态。
- 选购读取实时清单、最近商品卡片与已保存条件。有线/无线/蓝牙按商品规格筛选，尚不是任意条件的通用约束引擎。
- 预算默认约束本次新增采购，明确指定整张清单时才按全单核算；商品卡按已知数量与预算筛选并统一排序。
- 指定商品的待确认操作随会话保存，可补数量、修改或取消。确认时重新核对价格与清单版本；按名称删除及清空需要确认，重复确认不会重放旧操作。
- 对话资料查询融合关键词与向量候选，采用 RRF 排序；关键词部分是字串匹配，不是 BM25。无向量时明确降级。改变索引模型或维度需要重建。
- 生成文本通过鉴权 SSE 增量返回，路由与工具执行仍需等待。采购回执与最终清单摘要由服务端生成，不是所有阶段都逐 token 输出。
- 模型准备清单与确认入口，下单、支付、取消由用户操作业务接口完成；普通购物和助手共用交易规则。

默认不调用模型，须配置自己的百炼 Key。向量索引另行准备；没有 Key 时仍能普通购物和人工采购。新安装不携带开发者私人 OSS 图片。

后端自动化检查入口为 `scripts/Build-Xucai.ps1`；前端在 `web` 目录运行 `npm test`。真实模型调用、外部Redis契约和完整业务演示需要配置相应运行环境。

自动化测试验证具体行为，不代表模型对任意问法均能正确回答。不含真实支付、物流或生产可用性承诺；资料保留地区与版本，不能把未知说成确定支持或不支持。

## 权限设计

JWT校验身份，网关按公开、客户、商家接口执行固定角色授权，未开放路径默认拒绝；业务层继续校验订单、需求和会话的数据归属。角色信息保留在数据库，接口权限当前由代码集中维护，不提供动态权限配置后台。

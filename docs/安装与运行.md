# 安装与运行

以下用于新建本地演示环境，不对现有数据库做升级。真实凭据只留`.runtime`，不要提交到Git。除明确进入 `web` 或 Docker 私有目录的步骤外，命令均从项目根目录执行。

## 1. 中间件

```powershell
python scripts/prepare_local_dependencies.py --create
```

生成新的`.runtime/local-dependencies`，含Compose、独立随机密码和应用账号SQL。目录存在即拒绝，失败保留；不要删目录重跑来给现有容器换密码。

在Docker宿主机使用这个私有目录，并确认目标容器/卷/网络和端口不存在。Linux目录权限0700，三个挂载文件需可供容器服务用户读取。使用唯一且固定的项目名：

```sh
docker compose -p xucai-local-demo -f compose.yml up -d
```

模板默认MySQL13306、Redis Stack16379、Nacos18848及gRPC19848，均仅绑定宿主机127.0.0.1。Nacos本机发现关闭鉴权，不用于公网；不需要MQ或真实支付服务。镜像使用MySQL8.0.29、Nacos2.4.2、Redis Stack6.2.6-v19，可在`.env`中配置镜像和端口。

如果Docker在VM，使用系统OpenSSH纯端口转发，并在服务运行期间保持：

```powershell
ssh -N -T -o ExitOnForwardFailure=yes -o ServerAliveInterval=15 `
  -L '127.0.0.1:13306:127.0.0.1:13306' `
  -L '127.0.0.1:16379:127.0.0.1:16379' `
  -L '127.0.0.1:18848:127.0.0.1:18848' `
  -L '127.0.0.1:19848:127.0.0.1:19848' <SSH用户>@<VM地址>
```

左侧Windows端口必须空闲，右侧与实际VM映射一致。若VM已有16379，可把新容器映射其他端口，再仅修改该项右侧；应用仍通过16379满足隔离规则。

### MySQL 8 首次认证公钥

MySQL 8 新建账户默认使用 `caching_sha2_password`。本地演示通过回环/SSH隧道连接时，需固定该 MySQL 实例的认证公钥，避免首次连接报 `Public Key Retrieval is not allowed`。

容器就绪后，在可信 Docker 宿主机执行（项目名与前文一致）：

```sh
docker compose -p xucai-local-demo -f compose.yml cp mysql:/var/lib/mysql/public_key.pem ./mysql-public.pem
```

这是服务器**公钥**，不要复制 `private_key.pem`。通过已有可信 SSH/SFTP 将它复制到应用机器的私有运行目录。在环境脚本设置 `XUCAI_DB_RSA_PUBLIC_KEY` 为该文件的绝对路径，使用正斜杠且路径不含空格。不要从不可信网站下载公钥；不要通过关闭校验或打开任意公钥获取来掩盖认证问题。旧 `mysql_native_password` 账户可留空，新实例应配置此项。这里的非TLS连接仅适用于已说明的回环/SSH隧道演示，远程部署另行配置TLS。

## 2. 五个新采购库

```powershell
python -m pip install pymysql requests
python scripts/bootstrap_database.py
# 在本机私下配置XUCAI_BOOTSTRAP_HOST/PORT/USER/PASSWORD。
# 连接新的MySQL13306；管理员密码在私有credentials.json，不给应用使用。
python scripts/bootstrap_database.py --apply
```

五库必须都不存在。脚本按001—016创建采购表及两个演示账号，不调用模型。MySQL DDL不是整批事务；失败留下INCOMPLETE和最后意图，禁止删除检查点盲目重跑。Compose首次数据卷初始化创建`xucai_app`，只授权五库DML；应用不能使用root。

## 3. 构建与启动

```powershell
./scripts/Build-Xucai.ps1 -Online -Goal package -JavaHome '<JDK17目录>' -Maven '<mvn.cmd路径>'
# 后续离线复用同一缓存：
./scripts/Build-Xucai.ps1 -MavenRepository .runtime/maven-repository -Goal package -JavaHome '<JDK17目录>' -Maven '<mvn.cmd路径>'
python scripts/generate_local_keystore.py --java-home '<JDK17目录>'
Copy-Item config/portable.env.example.ps1 .runtime/portable-env.ps1
# 私下填写新应用账号/Redis密码和实际地址；模型及向量开关保持false。
. ./.runtime/portable-env.ps1
./scripts/Start-Xucai.ps1 -JavaHome '<JDK17目录>'
```

发布入口默认portable,xucai，仅使用本机配置，Nacos仅服务发现。JWT仅在`.runtime/portable-jwt`新建，不复制别人的JKS，不覆盖现有目录。等待六应用Started和XUCAI注册健康；启动命令返回PID不代表已就绪。

同机第二套须用独立源码目录、状态、JWT、数据库和Nacos，可设置`-PortOffset 10000 -MaxHeapMb 256`；不能只改端口而共享原注册中心和数据库。默认网关10010，第二套20010。

## 4. 导入与浏览

```powershell
python scripts/import_catalog.py --manifest all --output .runtime/catalog-preview.json
python scripts/import_catalog.py --manifest all --apply --output .runtime/catalog-import.json
cd web
npm ci
npm test
npm run build
cd ..
./scripts/Start-XucaiWeb.ps1 -NodeExe '<node.exe路径>'
```

新环境导入20款公开商品，价格/库存为演示值，资料保留来源与地区限制。检查点不可删除；商品同名但无创建记录会拒绝认领，已投入业务的库存/售价不会重置。第二套导入显式指定`--base-url http://127.0.0.1:20010`，旧检查点不能切换网关。

新库内置虚构演示账号：客户 `buyer_demo`、商家 `merchant_demo`，密码均为 `XucaiDemo2026!`。仅用于本地演示，不可作为真实经营账号；收货信息也应使用虚构数据。

另附可选的 `scripts/fixtures/m720-china-supplement.json`，它是2026-09-18核对的M720中国官网资料，未混入原商品导入清单。在商家商品编辑页找到对应M720，将其中标题、来源和正文作为新资料保存即可；如已有该来源，不重复创建。它补充连接和切换说明，不将原美国货号转换为中国货号。使用语义检索时再显式更新该商品索引，此操作会调用已配置的向量模型；没有模型配置也可浏览原文和使用关键词检索。

浏览器访问5173，按双端入口登录。前端默认代理10010，不要用它误操作第二套；第二套在对应源码目录运行 `./scripts/Start-XucaiWeb.ps1 -Port 5174 -ApiPort 20010 -NodeExe <node.exe路径>`，浏览器访问5174。配置只接受本机HTTP后端；停止脚本按记录的端口核对进程。直接使用Vite时可显式设置服务端环境变量XUCAI_API_ORIGIN=http://127.0.0.1:20010，该值不会打入浏览器JS。

验证人工主链：客户手填需求→商家选品、选原文→逐项核实发布→客户确认→DEMO支付→商家登记虚构物流→收货→售后咨询与处理。无需模型Key。`verify_portable.py --base-url ... --output ...`验证登录与权限。

仅在刚导入的第二套空交易环境，可运行`verify_fresh_demo.py --base-url http://127.0.0.1:20010 --output ... --execute`；默认离线计划，完成后resume零请求，失败不自动重试。它会创建一笔演示交易，不是通用初始化器。

停止时从对应项目根目录运行以下命令，再核对项目名并停止对应 Compose 容器。保留数据卷和所有检查点，不把删除数据当作重启。

```powershell
./scripts/Stop-XucaiWeb.ps1
./scripts/Stop-Xucai.ps1
```

同机不同端口不会隔离Cookie。两套环境同时登录时请使用不同浏览器配置文件，或一套使用独立隐私窗口，避免刷新登录Cookie互相覆盖。当前启动脚本依赖Windows网络和进程API，不支持直接在Linux/macOS运行。


## 5. 开启聊天助手与商品图片（可选）

新安装默认关闭模型与向量调用。普通浏览、采购清单和人工方案流程不需要模型 Key；登录后可打开正式助手界面，但生成回答需要下面的模型配置。`/design/assistant` 是开发环境的固定回复交互预览，仅在 `npm run dev` 下可访问，不是正式助手；生产构建不包含该入口。

在私有环境脚本中设置 `XUCAI_REQUIREMENT_MODEL_ENABLED=true`、`XUCAI_DASHSCOPE_KEY` 和本账户可用且代码支持的 `XUCAI_GENERATION_MODEL`（目前白名单为 `qwen3.7-flash-2026-07-15`、`qwen-plus-2025-12-01`；其他型号需要兼容验证及代码修改，不能直接填任意名称），再启动或重启 AI 应用。Key 不放前端或 Git。生成服务启用后，登录客户端即可打开浮窗；先搜索商品，再咨询资料或调整清单，点击确认入口后由本人填写地址和下单。

没有向量索引时资料工具使用关键词读取，不能称为语义检索。`XUCAI_RETRIEVAL_ENABLED` 只控制检索开关，不会自动建立索引。聊天、需求整理、候选与向量调用均保留用量记录、单次输入边界和有限执行，不再限制本地累计次数或金额；云账户余额和限流仍有效。

图片配置通过环境变量 `XUCAI_OSS_CONFIG` 指向本机私有 JSON：

```json
{
  "endpoint": "https://oss-cn-shanghai.aliyuncs.com",
  "region": "cn-shanghai",
  "bucket": "your-private-bucket",
  "prefix": "products/",
  "accessKeyId": "<在本机填写>",
  "accessKeySecret": "<在本机填写>"
}
```

仅给应用该 Bucket 的 `products/` 前缀读写权限，保持 Bucket 私有；应用不需要管理 Bucket 或删除对象的权限。配置后重启目录应用，登录商家端，先停售并保存商品，再上传 JPEG/PNG（不超过 2MB），检查图片后恢复在售。上传会更新商品版本，旧确认或方案可能需要重新核实。发布副本不携带开发者 OSS 凭据、图片对象或原数据库关联；新导入商品显示分类占位，上传自己的素材后显示实物图。

建议体验顺序：普通浏览→加入清单→确认→取消；聊天选品→问资料→调整数量→本人核对清单；最后再试复杂草稿→保存需求→商家方案。所有付款、物流仍为演示。

## 7. IDEA 运行与调试

打开本项目pom.xml、选择JDK17并加载Maven模块后，可使用`.run/`中的六个Java Application配置启动Spring Boot，也可选择“序采-全部后端”。前端配置需要IDE支持Node/npm；否则在web目录运行`npm run dev`。停止原脚本启动的服务再启动IDE，避免端口冲突。

运行配置从`.runtime/idea-private.properties`读取私有配置，不依赖.env插件。先按前文设置本机XUCAI环境变量，然后在项目根目录PowerShell终端生成自己的JSON与属性文件：

```powershell
New-Item -ItemType Directory -Force .runtime | Out-Null
$localSettings = @{}
Get-ChildItem Env:XUCAI_* | ForEach-Object { $localSettings[$_.Name] = $_.Value }
$localSettings | ConvertTo-Json | Set-Content .runtime/idea-env.json -Encoding UTF8
python scripts/prepare_idea_config.py --source .runtime/idea-env.json
```

更新设置后加`--overwrite`重新生成。两个私有文件均不得提交或分享。文件缺失会停止启动；所有配置沿用portable,xucai profiles，AI启用IPv4。单独选择应用并点击Debug即可打断点；首次需编译。Compound不负责等待依赖就绪。
